# @lowdefy/blocks-native

The native block set: React Native components a Lowdefy mobile shell renders through `@lowdefy/client-native`. Each block keeps its web block's type name, properties, events, methods and slots, so one page can be shared by web and mobile.

## Blocks

Layout and display blocks: `Box`, `Card`, `Divider`, `Tabs`, `Title`, `Paragraph`, `Markdown`, `Icon`, `Tag`, `Alert`, `Empty`, `Skeleton`, `Spinner`, `PageDots` and `Illustration`. `AgentChat` is the agent chat (below). List, input and action blocks: `List`, `ListItem`, `Avatar`, `StatusIcon`, `TextInput`, `TextArea`, `NumberInput`, `Selector`, `ChipSelector`, `Switch`, `DateSelector` and `Button`. `Screen` (the mobile page type) has its meta here and its component in `@lowdefy/client-native`. `Empty`, `ListItem`, `Avatar`, `StatusIcon`, `ChipSelector` and `PageDots` have no web block; a page that uses one is mobile only. Box's `onSwipeLeft`, `onSwipeRight` and `swipeFeedback` are mobile only.

| Block                 | Web source          | Native notes                                                                                    |
| --------------------- | ------------------- | ----------------------------------------------------------------------------------------------- |
| `Box`                 | blocks-basic        | A `View`, or a `Pressable` button with `onClick`; swipe events (see Swipes below).              |
| `Card`                | blocks-antd         | Header (title, extra), cover, body, actions; `loading` draws skeleton rows.                     |
| `Divider`             | blocks-antd         | Dashed and dotted lines are zero-height views with a split border (iOS draws dashes only so).   |
| `Tabs`                | blocks-antd         | Top tabs in a scrolling bar (RN views, not `@expo/ui`); `setActiveKey` method; `bottom` too.    |
| `Title`, `Paragraph`  | blocks-antd         | Text styles from antd's typography; `ellipsis` with expand/collapse fires `onExpand`.           |
| `Markdown`            | blocks-markdown     | Read-only GFM drawn with RN views by `react-native-marked` (below); `onLinkPress`, `linkChips`. |
| `Icon`                | blocks-basic        | Drawn by the native icon renderer; a button with `onClick`.                                     |
| `Tag`                 | blocks-antd         | Status and preset colours from the computed palette tokens; closable; `href` opens outside.     |
| `Alert`               | blocks-antd         | Type colours and icon; closable fires `onClose` then `afterClose`; `action` slot.               |
| `Skeleton`, `Spinner` | blocks-loaders      | A shimmering shape or `variant` layout (below); the platform `ActivityIndicator`.               |
| `Empty`               | none (antd `Empty`) | The empty tray or an icon, a description and a `footer` slot.                                   |

## Lists

- **Colours.** `shared/getSemanticColors` reads the iOS semantic colours (grouped background, cell, cell pressed, separator, label tiers) from the theme (`colorGroupedBackground`, `colorCell`, `colorCellPressed`, `colorSystemBackground`, `colorSeparator`, `colorLabel`, `colorSecondaryLabel`, `colorTertiaryLabel`, from client-native's semantic tokens), and falls back to the closest antd token (`colorBgLayout`, `colorBgContainer`, `colorFill`, `colorBorder`, `colorText*`). Colour names in config (`teal`, `amber`, `grey`, `colorSuccess`, `colorTint`, a hex) go through client-native's `resolveColor`: a hue is its mode-adjusted 6th shade, a token name is that token. It lives in client-native because the icon renderer resolves an icon's `color` (the Icon block's, a ListItem's leading icon, ...) with it too; a Selector option's `iconColor` goes through it in `shared/OptionGlyph`.
- **Type.** Rows and headers use the iOS text styles in `shared/iosTextStyles` (Headline title with a subtitle, Body alone, Footnote subtitle and headers), in the system font.
- **Sections.** `getSections` turns `header`, or `sectionKey` and `sections`, into SectionList sections. Without `sections`, neighbouring items with the same key share a section (the list order is kept); with it, every item joins its key's section in the order given, unlisted keys follow and empty sections are hidden.
- **Rows.** `ListRow` draws each item as a cell (inset, first and last rounded, clipped) and the hairline separator under all but a section's last row. It provides `ListRowContext`: a ListItem in the row sets the separator inset to its title (`getListItemParts` computes it; a `leading` slot is measured with `onLayout`) and swipes on the row's background.
- **Checkmark.** `trailing.check: true` draws the iOS checkmark accessory where the chevron goes: `shared/SystemIcon` with `checkmark` at 17pt semibold (a SwiftUI `font` modifier, `SystemIcon`'s `weight`) in `colorTint`, `Check` elsewhere. A checked row has no chevron unless `chevron: true`, and is `selected` to a screen reader. Multi-select lists in a sheet (labels) set it per row from state.
- **Swipe actions.** `shared/SwipeableRow` (Animated and PanResponder, JS driven): leading and trailing trays that grow with the drag, the first action at the edge, open past half, and a full swipe past 60% of the row runs the edge action on the sides `fullSwipe` allows (ListItem: leading by default). SwiftUI's SwipeActions only work inside a SwiftUI List, and List items are React Native views. No haptics: the shell links no haptics module.
- **Context menu.** On iOS `ListItemContextMenu` hosts the row in `@expo/ui/swift-ui`'s `ContextMenu` trigger (`Host` and `RNHostView`), its items as SwiftUI buttons with SF Symbols (`getSfSymbol`; a Lucide name shows no icon). It requires `@expo/ui/swift-ui` when drawn, so Android and the shell's Jest never load SwiftUI. Elsewhere a long press shows an alert (`showContextMenuAlert`). Screen readers get swipe and menu items as accessibility actions on the row.
- **Avatar and StatusIcon.** `getInitials` (first and last word, an email's name part) and `getAvatarColor` (an FNV-1a hash of the lower-cased name into nine antd hues, deeper shades for bright hues in light mode). `StatusGlyph` draws each glyph on a 16 unit grid with react-native-svg; marks inside filled glyphs use the cell colour so they read as cut out. `StatusMark` adds the label and accessibility, and is shared by StatusIcon, ListItem and section headers.

## Swipes

A Box with `onSwipeLeft` or `onSwipeRight` takes horizontal swipes, such as swiping through recent records (with `PageDots` for the place among them). `Box/useSwipeGesture` is a PanResponder on the Box (around its Pressable when it has `onClick`, since a Pressable sets its own responder handlers), and the thresholds are plain functions with tests:

- **Taking a drag.** `isSwipeGesture` answers the bubble-phase `onMoveShouldSetPanResponder` only, so rows inside the Box with their own swipes (a ListItem's swipe actions take the capture phase) win, and a press inside the Box is cancelled once the Box takes the drag. It takes a drag that `getSwipeDirection` calls a swipe (across more than 40pt and more than twice as far across as down, or a flick faster than 0.5pt/ms past 10pt) in a direction the Box has an event for, and never one that started within 20pt of the screen's left edge (`moveX - dx`), which is iOS's back gesture. Vertical drags stay with the page's scroll view. Once taken, the Box refuses to give the drag up.
- **Release.** The pan responder measures from its grant, so the hook keeps the distance it took the drag at and judges the release on the whole drag: a drag dragged back short of a swipe fires nothing.
- **Feedback.** `swipeFeedback: true` moves the Box on a rubber band (`getRubberBand`: iOS's `1 - 1 / (x * 0.55 / 48 + 1)` stretch, never past 48pt) from where it took the drag, so it does not jump by the 40pt, and only toward a direction it has an event for; it springs back on release, on the native driver.
- **Native scroll views inside.** A UIScrollView's pan recogniser takes a drag natively, before the JS responder system negotiates, and cancels the JS touch (`cancelsTouchesInView`), so no capture or bubble choice in the Box can win a drag a horizontal scroll view inside it begins. A ChipSelector therefore scrolls only when its chips overflow (`scrollEnabled`, and `alwaysBounceHorizontal: false`), so a strip that fits leaves the drag to the Box. The Box provides `shared/SwipeContext` (`{ directions, swipe }`, only a Box with swipe events, so a plain Box between leaves it); a strip that overflows passes a drag released past an end it cannot scroll further toward (`getOverscrollSwipe`: 20pt past, about the 40pt drag under iOS's rubber band, or a flick past 0.5pt/ms) on as the Box's swipe that way, from `onScrollEndDrag`. Android does not scroll past the ends, so there a swipe across an overflowing strip only scrolls it.
- **Screen readers.** Each swipe event is an accessibility action (`swipeLeft`, `swipeRight`) on the Box's accessible element.

`PageDots` is iOS's page control: `count` 7pt dots 9pt apart in `color` (a hue, token or hex through `resolveColor`; the label colour by default) at 30%, and an active dot over them in full that slides to `index` on a spring as it stretches across and settles round (native driver). Screen readers read "Page 2 of 5". An index past the end shows the last page.

## Illustration

`Illustration` draws SVG markup (`svg`) with keyframe `animations` of its elements by id, such as a mascot that blinks and hops. It adds no native module: react-native-svg draws and React Native's `Animated` animates, on the native driver. The shell links no Reanimated.

- **Parsing.** `parseIllustration` reads the markup with react-native-svg's own `parse` (its middleware hands over the tree before it becomes elements) into `{ tag, Tag, props, children }` nodes, `Tag` being the component that draws the element. Root definitions (`defs`, gradients, clip paths, masks, patterns, symbols, filters, markers) are kept apart. The viewBox (or a numeric width and height) is required. `<style>` sheets and classes are not drawn.
- **Colours.** `var(--name)` in any attribute or style declaration is replaced (`colorNodes`) by a colour from `getIllustrationColors`: the theme's string tokens, then `colors`, then in dark mode `colorsDark`, each through `resolveColor` (hue, token or CSS colour). `var(--name, fallback)` falls back as CSS does; a name with neither throws.
- **Layers.** The native driver animates a view's `transform` and `opacity`, never an SVG element's attributes, so `getLayers` splits the drawing in paint order: runs of unanimated elements are drawn layers (an `Svg` each, inside their ancestor groups, ids dropped, with the definitions repeated), and each targeted element is an animated layer, an `Animated.View` filling the drawing (no backing store of its own) with its own layers inside. Groups holding targets are split around them, so a target in a target moves with it. Unanimated elements share one layer unless an animated one sits between them in paint order, so art drawn with its still parts first costs one still layer.
- **Cropping.** An `Svg` keeps a backing store of its size, so each drawn layer's `Svg` covers only the part of the viewBox it draws in (`getLayerBounds`: every point its shapes name, a path's control points included, half the widest stroke and a unit of margin, whole units, within the viewBox) with a matching viewBox. A layer with a transform, an arc, text, an image, a `use` or a size it cannot read covers the whole viewBox.
- **Motion.** `createIllustrationMotion` gives animations with the same duration, delay and loop one clock (an `Animated.Value` from 0 to 1), so frames that swap on the same keyframe swap on the same frame. `getKeyframeRange` turns keyframes into the clock's interpolation: the native interpolation is linear, so an eased segment is sampled at 12 points along its curve, and `step` holds each value until just before the next keyframe. Translations are drawing units scaled to points; several animations of one target and property add (translations, rotations) or multiply (scales, opacity); transforms apply about `origin` (`transformOrigin`, the viewBox centre by default). `useIllustrationMotion` runs each clock (`Animated.loop`, after `delay`) while the block's screen is shown (`useScreenFocused`); a hidden screen stops them, and they start their cycles again when it shows. With Reduce Motion on, nothing runs and each animation holds its value at the start of its cycle.
- **Placement.** `getIllustrationBox` fits the viewBox whole and centred in `width` × `height` (either from the other and the aspect ratio). With `position` (`{ top, right, bottom, left }`) the box is absolute at those offsets from the block's place and takes no room. For art beside a large title, the block goes in the Screen's `headerBackdrop` slot (aligned with `alignSelf: flex-end`, reaching down beside the first content with a negative `marginBottom`), not in the content with a negative offset. The box never takes touches (`pointerEvents: none`). Without a `title` it is hidden from screen readers; with one it is an image of that name.

## Chip strips

`ChipSelector` is a space switcher in the style of Linear's and GitHub's iOS apps: a horizontal `Animated.ScrollView` of chips, 16pt leading and trailing padding and 8pt between chips.

- **Chip.** 32pt tall, 16pt radius (continuous corners), a 1pt border that is clear until selected (so selection never moves the layout). A 20pt rounded-square tile (radius 6) holds the option's Lucide icon at 13pt, then the label in Subheadline semibold and an optional `badge` in Footnote semibold with tabular numbers. Pressing scales the chip to 0.97 (`Animated`, native driver) and springs back.
- **Colour.** `getChipColors` reads the option's `color`: `{ fg, bg, fgDark, bgDark }` is a mark drawn fg on bg (as a workspace's mark on the web), a string is a palette hue, token or hex through `shared/resolveColor` drawn as a tile with a white icon, and no colour is `colorTint`. Unselected chips sit on `colorSystemFill` in `colorLabel`; the selected chip fills with bg (or the colour at 15%, 24% in dark mode, through `withAlpha`) with its border and label in the colour, and a mark's tile flips to fg with the icon in bg so it stays visible on the bg fill. Dark mode takes the dark variants, and never a mark's light bg.
- **Scrolling.** `getScrollTarget` scrolls as little as brings the selected chip into view, 24pt clear of the edge (the fade): without animation once the strip, its content and the chip are laid out (`onLayout`, `onContentSizeChange`), animated on each later change. `getFadeRanges` gives each edge fade an interpolation of the native-driven scroll offset, so the leading fade grows in over the first 24pt scrolled and the trailing one fades out over the last; none while the content fits. The fades (`EdgeFade`, react-native-svg gradients) go from `fadeColor` (the grouped background by default) to clear, since React Native has no alpha mask without a native module.
- **Scrolling only when needed.** The strip scrolls only when its chips overflow, and never bounces when they fit, so a Box with swipe events around it takes swipes across it (see Swipes).
- **More chip.** `moreChip: { label, icon }` adds a trailing chip, its icon drawn plain, that fires `onMore` (a Sheet of every option) and sets no value.
- **Edge to edge.** In an area that provides `EdgeInsetContext` (a Screen's `headerBottom`), the strip cancels the area's padding with a negative margin so it scrolls to the screen edges.

## Selector rows

`variant: menu` and `variant: sheet` draw an iOS Settings-style property row (`SelectorRow`): the title at the left, the chosen option at the right with its glyph or avatar (`shared/OptionGlyph`), its label and an up-down chevron, or the placeholder. The row is `shared/PropertyRow` (at least 44pt, 16pt by 10pt padding, the title in Body in the label colour, the value and placeholder in Body in the secondary label colour from `shared/getPropertyRowTextStyles`), which NumberInput, TextInput and DateSelector `variant: row` draw too (see Property rows below), so a List mixing them lines up to the point. Put it in a `Card` with `padding: none` for an inset grouped look. Both set the value through `setSelectorValue`, so a pick fires `onChange` (and `onClear` for the no-value item) the same way, and picking the chosen option changes nothing. The no-value item (the placeholder) is listed while there is no value or `allowClear` is not false.

- **Menu.** `SelectorMenu` opens a native menu (`shared/NativeMenu`, @expo/ui's community `MenuView`) with `getSelectorMenuActions`. Native menus draw SF Symbols only, so an option with an avatar shows `person.crop.circle`.
- **Sheet.** `SelectorSheet` opens `PickerSheet`, an @expo/ui community `BottomSheet` used as the Sheet block uses it (the elevated background when the app forces the other colour mode), so rows can draw pictures. The header centres `menuTitle` (the Selector title by default) with `shared/SheetCloseButton` at the right. A search field (`PickerSearchField`: the tertiary fill, a `magnifyingglass` glyph, a clear button) shows when there are more options than `searchThreshold` (7); `normalizeSearchText` makes the match case- and diacritics-insensitive (NFD, combining marks dropped). `getPickerSheetRows` orders the rows: the pinned group (the no-value row, then options with `pinned: true`), a full-width hairline, then the rest; separators are inset to the label. A row (`PickerOptionRow`) is 52pt: the leading glyph (`PickerRowLeading`: a 28pt `AvatarCircle` with the picture over the initials, a 20pt SF Symbol or icon, or the dashed circle `NoValueAvatar` for the no-value row; no leading space when no option has a glyph), the label in Body, `description` in Footnote secondary, and a `checkmark` in `colorTint` on the chosen row. Rows are buttons with `selected` and `disabled` accessibility states; a disabled option is dimmed and cannot be picked. `getPickerSheetDetents` keeps a list that fits at half height at the medium detent alone (no drag indicator); a longer list, or one with a search field, gets medium and large, and focusing the search field moves to large. The FlatList keeps taps while the keyboard is up, adjusts its insets for the keyboard (`automaticallyAdjustKeyboardInsets`) and opens scrolled to a chosen row below the medium height (`getPickerSheetScrollIndex`). Rows mount from opening until the sheet is dismissed; the search clears on dismissal. There is no haptic feedback: expo-haptics is not a dependency.

## Property rows

`variant: row` on NumberInput, TextInput and DateSelector draws the input as an iOS Settings row with `shared/PropertyRow`, the row Selector `variant: menu` draws: the title at the left (the Label draws no title above, only the validation message and extra text under the row), the value right-aligned at the right in the secondary label colour, and the placeholder ("Not set" by default) in the same colour. Put them in an insetGrouped List or a Card with `padding: none`.

- **NumberInput and TextInput.** The value is the `TextInput` itself (`textAlign: right`, `flex: 1`, no padding), so it stays right-aligned while editing, and pressing anywhere on the row focuses it (`ref.focus()`), with the number keyboard for a NumberInput. Prefix and suffix sit beside it in the value style. A NumberInput row has no step buttons; a TextInput row with `allowClear` shows the clear button while focused.
- **DateSelector.** The row is a `NativeMenu` trigger with the value and the up-down chevron, as a Selector menu row. `getDateMenuActions` gives Today, Tomorrow and Next week (a week from today, as UTC days from `toUtcDay`), the one the value is on checked and any outside `disabledDates` dimmed, then "Pick a date…", which opens the inline calendar under the row, and Clear (destructive) while there is a value and `allowClear` is not false. The compact iOS date picker was not used: it draws its own tinted pill, not a Settings value.

## Markdown

`Markdown` draws GitHub-flavoured markdown (headings, emphasis, strikethrough, code, block quotes, ordered, unordered and task lists, tables, images, links) with React Native views. It takes the web block's `content` and `skipHtml`, and adds `onLinkPress` and `linkChips`.

- **Library.** `react-native-marked` parses with `marked` and draws with `Text`, `View` and `Image`. Its native peers are `react-native-svg` and `expo-web-browser` (for the in-app browser), which the `basic` profile already links, so the block adds no native module and reaches shells in an update. `react-native-markdown-display` was not chosen: its last release was in 2023, on `markdown-it` 10. A web-view `Markdown` costs a web view per instance.
- **Scrolling.** The block uses the `useMarkdown` hook, not the library's `FlatList` component, because a block sits in the page's scroll view.
- **Theme.** `getMarkdownStyles` maps the iOS semantic tokens onto the library's styles (body text, headings in the title1 to footnote text styles, inline code on `colorTertiarySystemFill` in the platform's monospace font) and gives a `palette` the block's own components draw with.
- **Drawing.** `MarkdownRenderer` replaces most of the library's drawing: lists with a marker column, bullets and numbers by depth (`MarkdownList`, `getListMarker`, depth through a context), fenced code as a rounded card with its language that scrolls sideways (`MarkdownCode`), quotes with a tint bar, tables in a rounded box with a semibold header row and columns measured once (`MarkdownTable`), hairline rules and rounded images. `trimOuterSpace` drops the space above the first and below the last element.
- **Links.** Every link, wherever it sits (headings, emphasis, lists, quotes, table cells), presses through one handler. With `onLinkPress` the block triggers the event with `{ href }` and opens nothing; without it, an http(s) link opens in the in-app browser (`expo-web-browser`) and any other through `Linking.openURL`. The library reads an href without a scheme from the app root, so `page` passes `/page` and `#notes` passes `/#notes`.
- **Link chips.** A link that matches a `linkChips` entry is a `LinkChip`: an inline pill with the chip's icon, the key and the title, tinted by `tone` (`getLinkChipColors`), one line wide at most the block's width (`ChipWidthContext`). An entry matches by `scheme` (`acme:ACME-12`) or by `pattern`, a regular expression tested against the href as written, for the app paths an agent writes record links as (`[ACME-12 (Fix the menu)](/ACME/tasks/ACME-12)` with `^/ACME/tasks/(?<key>ACME-\d+)$`); the first entry that matches draws the link (`matchLinkChip`, each pattern compiled once). The key is the value after the scheme, or the pattern's `key` group (else its first group); link text that starts with it gives the title after it, without the brackets or separator between, and other text is the title after a pattern's key and all key after a scheme, whose value is often an id (`getLinkChip`). `label` shows `keyAndTitle` (default), the `key` alone, or the link `text`. Chips press through the host's link handler only: `onLinkPress` on Markdown and ActivityTimeline, `onLinkClick` or the `Link` action on AgentChat. An app's phone pages can rewrite `[[ACME-12]]` as `[ACME-12 Title](acme:ACME-12)` and `[[user:id]]` as `[@Name](mention:id)` for them. The library reads an href without a scheme from the app root, so `page` passes `/page` and `#notes` passes `/#notes`.
- **Raw HTML** is drawn as its source text, as the web block escapes it. With `skipHtml` it is left out.
- **Task lists.** The library draws no checkbox token, so `MarkdownTokenizer` puts a private-use mark in front of a task item's text. The renderer draws it as a `TaskMark`, which tells its list item (through a context, before paint) to draw a `TaskBox` where its marker goes.

## AgentChat

`AgentChat` is the web block's chat (blocks-antd-x) for a phone, drawn as ChatGPT's and Claude's iOS apps draw theirs. It takes the web block's properties, events and methods where a phone can honour them (`agentId`, `welcome`, `suggestions`, `sharedState`, `sharedStateReadOnly`, `urlQuery`, `conversationId`, `messages`, `loading`, `messageDisplay`, `sender.placeholder`); the web-only ones are `nativeIgnored`. The logic that does not draw (`messageParts`, `replayableMessages`, `useAgentEvents`, `useThinkingMessage`) is copied from the web block.

- **Transport.** `useChat` from `@ai-sdk/react` with `createAgentTransport`: the AI SDK's `DefaultChatTransport` posting `{ messages, urlQuery, pathParams, sharedState, sharedStateReadOnly }` to `/api/agent/{pageId}/{agentId}?conversationId=…`, as the web block's transport does, with its `fetch` the block's `methods.streamFetch` (client-native: the host's `expo/fetch`, the bearer session and the shell header; see code-docs/packages/client-native.md). The answer is the AI SDK UI message stream as server-sent events; the server resolves the shell's bearer caller on `/api/agent` as on every `/api/*` route. `ai` and `@ai-sdk/react` run on Hermes over Expo's winter runtime (`ReadableStream`, `TextDecoderStream`, `structuredClone`).
- **Layout.** The conversation is the page content, scrolled by the page's scroll view; `useFollowScroll` scrolls it to its end as a reply grows, on send and when the keyboard comes up, and stops following once the person touches the conversation (a "jump to latest" control in the composer follows again). The composer (`ChatComposer`) is drawn in the Screen's footer through `useScreenFooter`, pinned above the tab bar and the keyboard: a growing field with the send button in it (a stop button while a reply streams), a new-chat button, and the welcome prompts or follow-up suggestions as chips above it. It keeps its own text, so typing renders only the footer. `sender.sticky: false` draws it under the conversation instead, for a chat in a Sheet.
- **Messages.** The person's in a tinted bubble (`colorTintFill`) at the trailing edge; the agent's full width (`AssistantMessage`), its parts in segments as the web's `MessageBubble` makes them (`getMessageSegments`): reasoning behind a disclosure (`ReasoningDisclosure`), tool calls as compact rows (`ToolCallRow`, from `describeToolPart`: a glyph by the tool's verb, the humanised name, a one-line summary as the web's `summarizeToolOutput`, and the output as readable rows (`getReadableRows`, the native `formatToolResult`) when opened), approvals as cards with Reject and Approve (`ToolApprovalCard`), status updates while streaming, and text through `MarkdownContent`, the Markdown block's renderer (iOS typography, `linkChips`, outer space trimmed, web links in the in-app browser), so a reply reads as a Markdown block does; AgentChat takes the same `linkChips` property. Thinking dots and the rotating thinking message show until a reply has something to draw; a failed reply shows `ChatError` with Try again. A long press opens iOS's action sheet: Copy (a `CopyToClipboard` action) and, on a reply, Regenerate.
- **Client tools.** `update-page-state` writes the shared keys into the page state through a `SetState` the block registers, with the web's allowlist (`getPageStateUpdates`), and reports written and ignored keys back.
- **Links.** `onLinkClick` when wired; otherwise a `Link` action with the href, so an app path opens as a page and anything else leaves the app.
- **Threads.** With `threads` (`useChatThreads`) the block keeps its conversations through the ai-assistant module's endpoints (`threads.module` names the entry; `threads.endpoints` names any of them, for an app's own), called through one registered `CallAPI` event: it resumes the thread last opened (`get-active-thread`; a chat the person starts with `newChat` or opens from the sheet while it loads cancels the resume, so its answer cannot replace that chat), saves a thread when a message is sent (named by it, `getProvisionalTitle`) and when each reply finishes (`save-thread`), names it from its first exchange (`title-thread`, `getFirstExchange`), and lists threads in a sheet (`ThreadsSheet`, `list-threads`) opened by the `openThreads` method (a Screen header action), where a row opens one (`get-thread`) and a swipe deletes it (`delete-thread`). A sent message is saved as its request is made (the transport's `onRequest`), before its reply can finish. Without `threads` the app keeps them through `conversationId` and `messages`, as on the web.
- **Seeds.** A chat can start about a record: the `newChat` method takes `{ sharedState, welcome, input, tag, title }` as its args, and the `seed` property takes the same object for a chat that mounts with no thread resumed (`getChatSeed` keeps the parts it names). The thread keeps its seed (`useChatThreads`' `seed`): its shared state is merged under the page's `sharedState` for that conversation (the page's keys win, so a key update-page-state writes reads back), its welcome is laid over `welcome` while the chat is empty, its input fills the composer once no resume can replace the chat, and with `threads` its tag is saved in place of `threads.tag` and its title names the thread, so no title is generated from the first exchange. The composer's new-chat button starts an unseeded chat; one that is empty and unseeded is kept rather than replaced.
- **Not on mobile.** Attachments (the `basic` profile has no file or image picker), feedback thumbs, editing and deleting messages, sources, the sender's switches and header, and the drawer display.

## Metas

Each `meta.js` mirrors the web meta (copied, not imported, so the shell never installs web block packages). Two additions:

- **`nativeIgnored: true`** on a property a phone cannot honour (`hoverable`, `copyable`, `animated`, `target`, input `label.align` and `label.span`, `prefixIcon`, ...), with "Ignored on mobile" in its description. The schema still accepts the property, so a shared page stays valid. `extractBlockTypes` lists the marked paths in the block meta, and the build warns once per page for each one a page sets (`validateNativeIgnoredProperties`). Mark every property whose description says it is ignored on mobile, nested ones included.
- Descriptions say where mobile differs: "supports html" text is shown plain (tags removed by `htmlToText`), events that never fire on a phone say so.

## Theme and styles

Blocks read the computed antd tokens of the mode showing with `useTheme()` from `@lowdefy/client-native`; `useComponentTokens` lays a block's own `theme` property over them, as antd applies component tokens. Component tokens antd derives from global ones (`bodyPadding`, `headerHeight`, `cardBg`) fall back to those global tokens. Every block lays its own defaults and tokens under the `styles` slots the renderer passes (`element`, `header`, `title`, ...), so the order is block defaults, theme, class, style.

## Inputs

- Inputs draw `blocks/Label/Label.js`: title, `required` mark, colon (inline only), the `extra`
  text, and the first validation message once the engine shows validation. `getLabelState` holds
  the rules, which follow the web Label's `labelLogic`.
- The input box (`shared/getInputBoxStyle.js`) follows `variant`, `bordered: false`, `size` and
  the validation status. Sizes are one antd step taller than the web (`getControlSize`): a phone
  is touched, not clicked.
- Controls come from `@expo/ui` (a peer dependency the shell carries): `Picker` (Selector),
  `Switch`, and the community `DateTimePicker` (DateSelector). Picker and Switch sit in a
  `Host` seeded with the theme's primary colour and mode.

## Screen

`Screen` is the mobile page type. Its properties: `title`, `largeTitle` (an iOS large title that collapses as the page scrolls), `presentation` (`card`, `modal`, `sheet`), `backgroundTint` (`{ color, colorDark, height }`, a gradient wash of colour fixed at the top of the screen behind the bar and content, fading out at `height` of the screen, cross-faded on change; drawn by client-native), `headerSearch` (`{ placeholder, autoFocus, debounce, hideWhenScrolling }`, a native search bar) and `headerActions` (`[{ id, icon, sfSymbol, title, placement, event, disabled, items }]`, header icon buttons at their natural size, native SF Symbol bar buttons on iOS; with `items`, `[{ id, title, symbol, destructive, disabled }]`, the button opens a menu, a native UIMenu on iOS, and the picked item's id is the event's `_event: id`). Its events: `onFocus` (each time the screen is shown, after onMount the first time), `onRefresh` (turns on pull-to-refresh; the spinner holds until its actions finish), `onSearch` and `onSearchChange` (`_event: value` is the text; changes are debounced) and `onHeaderAction` (`_event: id`; an action's `event` names another). Its slots: `content`, `headerLeft`/`headerRight` for blocks drawn in the header at their natural size, and `headerBottom` for blocks pinned under the header (under the large title or the search field) as the page scrolls, such as a ChipSelector and a SegmentedControl: client-native draws it as the page's first content and moves it with the page's scroll offset and the shell's header inset (see code-docs/packages/client-native.md), `footer`, pinned below the scroll view above the tab bar and the keyboard (where a Composer goes), and `headerBackdrop`, blocks above the top of the content behind the large title and the bar, such as an Illustration beside the title, which scroll away with it (drawn by client-native, lifted by a transform). `src/blocks/Screen/examples.yaml` shows a list page, a list page with a space switcher and filter under the header, a detail page a search tab page, and a detail page with a backgroundTint.

## Icons

Blocks draw every icon through `components.Icon`, as on the web. `@lowdefy/client-native` installs it (`createIcon` over its `Icon` IconData renderer, the same renderer the shell's menus use), from `types.icons`, the icon data by name. The `Icon` block wraps it, as a button when it has `onClick`.

## Skeleton

`Skeleton` draws a placeholder shaped like the content that replaces it, so nothing jumps when data lands. `variant` picks the shape: `listRow` (a leading 22pt circle, a title bar 60 to 80% wide varied by row, shorter subtitle bars, an optional trailing 20pt circle), `insetGroup` (sections of rows in rounded cell cards with a header bar, at the inset grouped List's spacing; `count` may list each section's rows), `hero` (chip, key, two Title 1 bars, avatar and meta), `paragraph` (ragged body lines), `card` (paragraph lines in a cell card) and `timeline` (rail circles with one or two lines). Without a variant, `count`, `rows` or `avatar` draw list rows and anything else one shape of `width` and `height`.

- **Insets:** `insetGroup` and `card` inset their cards 16pt with margins; `hero` and `timeline` are inset 16pt by the element's `paddingHorizontal` (`VARIANT_INSETS` in `Skeleton.js`), laid under `styles.element`, so the element style's `paddingHorizontal` replaces it (0 is edge to edge). Bars are percentages of the padded box, so padding always insets them.
- **As a block's skeleton:** client-native's `LoadingBlock` splits the skeleton's `style` into slots (`getSkeletonBlock`, as the build splits a block's) and passes them as `styles`, so `skeleton: { type: Skeleton, style: { .element: ... } }` styles the Skeleton as the same style on a Skeleton block does.

- **Shimmer** (`src/skeleton/`): every shape is the `colorSkeleton` fill with a soft wide band of `colorSkeletonHighlight` sweeping left to right. One clock (`shimmerClock`, a 1.2s native-driver loop) runs while any shape is mounted, and each shape places the band by its x in its Skeleton block (`SkeletonFrameContext`, `measureLayout`), so all the shapes on a screen sweep as one band. With Reduce Motion on (`useReduceMotion` from client-native) the shapes are the plain fill and the clock does not run.
- **Bars** stand for an iOS text style (`skeletonText`): the bar sits in the style's line height, with round caps, so the text that replaces it takes the same room.
- **Accessibility:** the whole skeleton is one "Loading" progress bar.
- **Fade:** put `loading` and `skeleton` on the block that loads; client-native fades its content in when it stops loading (see client-native).
